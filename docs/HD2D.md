# MOSSBOUND HD-2D

기존 정령과 생존전 규칙을 유지하면서, 작은 원형 섬과 3D 캐릭터를 넓은 마을 지형과 2D 픽셀 스프라이트로 교체했습니다. 첨부된 이미지의 2D/3D 결합과 미니어처 같은 빛·렌즈 표현을 참고했으며 배경과 캐릭터를 직접 제작했습니다.

## 픽셀 캐릭터

`src/pixel-art.js`가 원본입니다. 48×64 RGBA 픽셀 격자에 팔레트 색상과 계단형 윤곽을 직접 그립니다. 정령 3종은 앞·오른쪽·왼쪽·뒤의 네 방향과 걷기 4프레임을 가집니다. 캐릭터는 `MeshStandardMaterial`을 사용하는 수직 평면으로 3D 조명을 받고, 카메라 방향으로 돌아서며 땅과 그림자를 공유합니다. Nearest 필터와 alpha test로 픽셀과 투명한 윤곽을 유지합니다. 도감·HUD의 초상화도 같은 원본으로 만듭니다.

`npm run sprites`는 정령 3종·일반 적 6종·보스의 192×256 PNG 아틀라스와 배치 설명을 `public/sprites/`에 출력합니다. 게임은 같은 원본을 DataTexture로 생성하며 외부 이미지 API를 호출하지 않습니다. 픽셀을 바꾸려면 원본 코드를 편집하고 내보내기를 다시 실행하세요.

## 지형과 카메라

이동 범위는 120×120m입니다. 높은 마을(약 3.6m), 동쪽 언덕(약 4.9m), 남쪽 고원(약 6.7m)과 낮은 물가를 연결하는 지형, 주변 숲, 여섯 채의 집, 물레방아, 우물, 성소, 개울과 다리 세 개를 배치했습니다. 지형 높이를 따라 캐릭터·적·경험치 씨앗이 이동합니다. 건물 충돌과 강의 통행 구간을 검사하며 대시도 벽과 강을 뚫지 않습니다. 적은 강 건너의 플레이어를 향할 때 가까운 다리로 우회합니다. 전투 중 시야를 가리는 나무는 인스턴스별 디더링으로 흐려집니다.

로비는 드래그로 회전하고 휠/핀치로 확대할 수 있습니다. **풍경 크게 보기**를 누르면 장면을 화면 전체로 확장합니다. 전투 카메라는 플레이어를 따라가며 미니맵은 플레이어·적·보스와 마을 구조를 표시합니다.

## 렌더링

- 태양의 방향광, 반구광, 랜턴의 점광원과 움직이는 그림자 영역.
- Reflector가 별도 시점에서 실제 장면을 렌더하는 수면 반사와 작은 수면 왜곡.
- 장면의 HDR 색상과 실제 depth texture를 렌더한 뒤, 플레이어의 카메라 깊이를 기준으로 근거리·원거리에 서로 다른 렌즈 블러를 적용하는 DOF.
- UnrealBloomPass의 하이라이트 블룸, OutputPass의 톤 매핑과 색 공간 변환. HTML HUD는 후처리에 포함하지 않습니다.
- 배경 나무·풀·돌은 인스턴싱하고, 설정의 **가볍게** 모드는 DOF·블룸·실시간 반사를 끄고 그림자와 렌더 해상도를 낮춥니다. 물 표면은 반사 대신 가벼운 재질로 표시합니다.

## 적의 역할

| 적 | 첫 등장 | 행동 |
| --- | --- | --- |
| 이슬 슬라임 | 시작 | 도약 속도에 맞춰 다가오는 근접 적 |
| 그늘 나방 | 시작 | 빠른 속도로 좌우로 흔들며 접근 |
| 독갓 버섯 | 15초 | 거리 유지·후퇴와 포자 탄환 |
| 길잃은 불씨 | 25초 | 플레이어 주위를 맴돌며 원거리 공격 |
| 가시등 딱정벌레 | 40초 | 0.85초 공격 예고 후 고정 방향 돌진 |
| 이끼 돌골렘 | 60초 | 체력이 높고 느리며 접촉 피해가 큰 적 |
| 가시왕 그루몽 | 스토리 150초 / 무한 모드 90초마다 | 돌진과 원거리 공격을 함께 사용하는 보스 |

## 검증

`npm test`의 15개 테스트가 공격 범위, 성장, 보스 조건, 무한 모드, 능력 잠금·초기화, 넓은 지형·다리 충돌, 포자 탄환 피해, 돌진 예고, 적 종류 해금, 픽셀 방향·프레임·투명도를 검증합니다.

`tests/visual.html`은 실제 World 렌더러에서 여섯 적을 함께 확인하는 개발용 장면입니다. 프로덕션 엔트리에 포함되지 않습니다. 브라우저에서 낮·밤의 픽셀 스프라이트, 수면 반사, DOF와 발광을 확인했습니다. 일반 플레이 화면에서도 기존 섬 경계 밖인 x=13m까지 이동하며 카메라·미니맵이 따라오는 것을 확인했습니다.

개발 브라우저의 한 번의 40프레임 표본은 약 77fps였습니다. 이는 해당 데스크톱 환경에서의 짧은 관찰이며 모바일 실제 기기 성능이나 장시간 부하를 보장하지 않습니다.

프로덕션 빌드에서 자동 처치·궁극기·일시 정지와 그림자 도감(7종)·정령 도감 탭 전환을 확인했습니다. 390×844 모바일 화면은 문서 너비가 390px로 가로 넘침이 없고, 조이스틱을 움직이면 `translate(24px, -16px)`이 적용되며 손을 떼면 초기화됩니다. 미니맵과 능력 버튼이 화면 안에 들어오는 것을 확인했습니다. 가볍게 모드에서 후처리·반사·그림자가 false, pixel ratio가 1이 되는 것도 실제 렌더러로 확인했습니다.

## 고저차와 대규모 전투 보완

마을 광장은 평평하게 유지하면서 주변을 평탄한 언덕 꼭대기와 연속적인 경사로 연결했습니다. 집의 부지는 평탄화하고, 다리 양쪽에는 낮은 진입로를 유지합니다. 계단 디딤돌·높이에 맞춘 울타리·고원 가장자리의 석축으로 높이 차를 보여 줍니다. 지형 메시는 192×192 분할을 사용하며 이동 시 지형 높이를 다시 계산합니다. 올라갈 때는 경사에 비례해 조금 느려집니다. 미니맵에도 고도에 따른 색과 현재 높이를 표시합니다.

실제 모험은 18마리로 시작합니다. 약 0.68~0.32초마다 4~8마리씩 증원되고, 20초마다 14~32마리의 추가 무리가 등장합니다. 일반 적 스폰 상한은 고품질에서 220마리, 가볍게에서 140마리입니다. 보스는 별도로 등장합니다. 공간 격자로 가까운 적끼리 분산시키고, 이펙트와 적 투사체 수를 제한하며 일반 적의 그림자는 가벼운 접지 그림자를 사용합니다. 모서리에서도 플레이어에게 최소 8m 떨어진 유효한 위치를 찾습니다.

적 투사체는 플레이어의 실제 높이를 향해 조준하며, 언덕에 닿으면 사라집니다. 피해 판정도 수직 거리를 포함합니다. 추가 테스트는 언덕 오르기·다리 진입로, 초기 무리·증원 주기·상한, 경사면의 투사체, 맵 모서리의 안전한 출현을 검증합니다.

`tests/visual.html?horde=1`에서 220마리의 대규모 장면을 확인할 수 있습니다. 데스크톱 개발 브라우저에서 첫 셰이더 준비 이후 60프레임 표본은 약 88fps였고 런타임 오류는 없었습니다. 실제 기기·전투 상황에 따라 성능은 달라집니다.
